# 合规事项管家（compliance-matter-manager）

对合规审查事项进行全生命周期管理：建档 → 台账登记 → 整改跟踪 → 期限提醒 → 复检 → 结案归档。

## 数据模型

- **台账索引**：`matters/ledger.json`（事项列表，JSON，零依赖）
- **事项档案**：`matters/{slug}/matter.md`（完整事项配置与记录，基于 matter-template.md）
- **数据安全**：matters/ 含企业敏感信息，仅存本地，禁止外发、禁止提交公开仓库（.gitignore 已排除）

## 工作流

### Step 1: 建档（收案）

用户提供事项信息（或由审查技能转来）：
1. 事项名称、类型（合同审查/贸易核查/国资交易/合规体检/采购审查/数据合规/劳动用工/境外投资/制度起草）
2. 业务责任部门、合规责任人
3. 完成/整改期限
4. 事项背景与关联材料

建档输出：
- 生成 `matters/{slug}/matter.md`（基于 matter-template.md）
- 更新 `ledger.json` 登记事项（状态：进行中）

### Step 2: 记录审查结论

各审查技能产出结论后，回写至事项档案：
- 审查结论（合规/基本合规/不合规；绿/黄/红）
- 发现问题清单
- 整改措施、责任部门、时限
- 更新台账状态（待整改）

### Step 3: 整改跟踪与期限提醒

- 按 due_date 检查到期事项
- 输出待办清单：`{事项} | 状态 | 期限 | 责任人 | 是否逾期`
- 逾期事项标红提示
- 提醒用户推进整改

### Step 4: 复检与结案

- 整改完成后标记"已整改"，安排复检
- 复检通过 → 状态"已关闭"，归档
- 复检未通过 → 回到"待整改"，更新整改计划

### Step 5: 台账查询

支持按状态/类型/责任人/期限查询：
- 全部事项、进行中、待整改、已整改、已关闭、已逾期

## 台账输出示例

```markdown
# 合规事项台账（截至 {日期}）

| 编号 | 事项 | 类型 | 状态 | 期限 | 责任人 | 逾期 |
|------|------|------|------|------|--------|------|
| 2026-001 | 铝锭贸易真实性核查 | 贸易核查 | 待整改 | 2026-08-20 | XX部 | 否 |
| 2026-002 | 采购合同合规审查 | 合同审查 | 进行中 | 2026-08-15 | XX部 | 否 |

## 逾期事项
（无 / 列出逾期事项）

## 本周到期
（列出 7 日内到期事项）
```

## 铁律

1. **数据真实性**：台账记录基于实际审查结论，不虚构事项和状态
2. **本地优先**：台账存本地文件，未配置协作平台时不用云
3. **敏感保护**：事项档案含内部信息，不随任何产出外发；对外报告仅输出汇总统计
4. **不阻塞主流程**：台账回写失败不阻塞审查输出，但标注"⚠️ 台账未更新"

## 联动说明

- 各审查技能产出结论后应调用本技能登记台账（回写协议见 matter-template.md）
- 期限提醒依赖台账数据，建议定期（每周）运行本技能生成待办
- 复盘见 /compliance-review
