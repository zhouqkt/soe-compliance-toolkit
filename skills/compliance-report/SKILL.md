# 合规报告生成（compliance-report）

汇总各项合规审查结论，生成结构化的合规风险报告、专项检查报告、整改报告等正式文件。

## 适用报告类型

| 报告类型 | 用途 | 结构特点 |
|---------|------|---------|
| 合规风险报告 | 全面反映合规风险状况 | 风险识别+评估+应对 |
| 专项检查报告 | 针对特定事项（贸易、合同、招采） | 检查情况+发现问题+结论 |
| 整改报告 | 针对问题整改情况上报 | 问题+措施+成效+下一步 |
| 自查报告 | 应上级要求开展的自查 | 对照要求+自查结果+承诺 |
| 年度合规管理报告 | 年度合规工作汇报 | 工作+成效+问题+计划 |

## 报告通用结构

```markdown
# XXX报告

## 一、基本情况
[背景、目的、依据、范围、方法]

## 二、工作开展情况
[组织实施、过程、数据]

## 三、发现的问题
[分条列明问题，注明严重程度：重大/较大/一般]

## 四、原因分析
[制度原因、执行原因、管理原因]

## 五、整改措施及建议
[分条列明，注明责任部门、完成时限]

## 六、结论
[总体评价、下一步工作安排]

附件：1.XXX
     2.XXX

XXX公司
2026年X月X日
```

## 报告生成工作流

### Step 1: 明确报告需求
请用户提供：
1. 报告类型
2. 报送对象（上级集团/董事会/国资委等）
3. 报告期间/检查期间
4. 审查结论素材（来自各审查技能的输出或用户提供）
5. 报送时限

### Step 2: 汇总素材
- 如有审查过程（如 rule-46-review 体检、trade-authenticity-check 核查），自动汇总其结论
- 用户补充的事实、数据、佐证材料

### Step 3: 起草报告
按报告类型对应结构起草，注意：
- 问题描述准确，附依据
- 整改措施具体可落地（责任部门+时限）
- 数据准确，不编造
- 语气符合报送对象（对上报告用报告语体）

### Step 4: 输出与排版
- 输出 Markdown 供确认
- 确认后生成 .docx（可按公文格式或企业格式排版）

## 报告写作铁律

1. **事实准确**：问题、数据以真实材料为准，不编造、不夸大
2. **问题分级**：重大/较大/一般问题分级标注，便于决策
3. **整改闭环**：整改报告须对应问题逐项闭环，注明完成情况
4. **口径一致**：与前期审查结论保持口径一致，不前后矛盾
5. **保密要求**：涉密内容提示线下处理，公开渠道不传输

## 输出前闸门（强制）

正式文件（审查意见书、核查意见、体检报告、制度文本、报告等）交付前，须过 /legal-verification 法规核验闸门（详见 Expert.md），核验全部法规、条文、监管文件引用；未核验的引用标注 `[L4-法规待核验]`，不得静默放行。

## Word 输出规范（统一）

所有正式 Word 文件统一使用套件脚本 `scripts/md2docx_gbt.py` 生成（GB/T 9704-2012 公文格式）：

```bash
python3 scripts/md2docx_gbt.py input.md output.docx --type gongwen
```

- 先输出 Markdown 供确认，确认后转 Word
- 脚本支持标记：`#`标题、`##`节标题、`|`表格、`>>`右对齐落款、`-`列表
- 文件命名：`{文种/事项}_{日期}.docx`
