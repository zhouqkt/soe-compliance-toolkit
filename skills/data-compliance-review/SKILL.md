# 数据合规审查（data-compliance-review）

对国有企业数据安全与个人信息保护工作开展合规审查，覆盖数据分类分级、数据处理活动、数据出境、网络安全等级保护等维度。

## 法规框架

- 《中华人民共和国数据安全法》（2021年9月1日施行）
- 《中华人民共和国个人信息保护法》（2021年11月1日施行）
- 《中华人民共和国网络安全法》（2017年6月1日施行）
- 《数据出境安全评估办法》（国家网信办令第16号）
- 《个人信息出境标准合同办法》
- 《网络安全等级保护条例》/《信息安全技术 网络安全等级保护基本要求》（GB/T 22239）
- 行业数据监管规定（金融、能源、交通等行业）

## 审查维度

### 一、数据分类分级
- [ ] 是否建立数据分类分级制度
- [ ] 是否对数据资产进行梳理和分级（核心数据/重要数据/一般数据）
- [ ] 重要数据目录是否向主管部门申报/备案
- [ ] 分级保护措施是否与数据级别匹配

### 二、数据处理合规（数据安全法视角）
- [ ] 数据收集是否合法正当（授权、范围）
- [ ] 数据存储是否安全（加密、访问控制）
- [ ] 数据使用是否合规（目的限制）
- [ ] 数据共享/交易是否合规（脱敏、协议）
- [ ] 数据删除/销毁机制是否建立
- [ ] 是否建立数据安全事件应急预案与报告机制

### 三、个人信息保护（个人信息保护法视角）
- [ ] 处理个人信息是否有合法依据（同意/合同/法定义务等）
- [ ] 是否履行告知义务（隐私政策）
- [ ] 敏感个人信息处理是否单独同意+必要性
- [ ] 个人信息处理者义务是否落实（安全措施、委托处理协议、个人信息保护负责人）
- [ ] 用户权利保障（查阅、复制、更正、删除）机制是否建立

### 四、数据出境
- [ ] 是否存在数据出境情形（向境外提供重要数据/个人信息）
- [ ] 重要数据出境是否履行安全评估
- [ ] 个人信息出境是否履行安全评估/标准合同/认证（三选一）
- [ ] 是否完成网信部门备案
- [ ] 境外接收方保护措施是否到位

### 五、网络安全等级保护
- [ ] 是否完成定级备案（等保）
- [ ] 是否按等级开展安全建设与整改
- [ ] 是否定期开展等级测评（三级每年测评）
- [ ] 关键信息基础设施运营者义务是否落实（如适用）

### 六、国企特别关注
- [ ] 是否落实数据安全责任制（领导责任）
- [ ] 数据安全考核是否纳入绩效考核
- [ ] 涉密数据管理是否合规（与保密制度衔接）
- [ ] 对外合作中数据提供是否合规（第三方、供应商）

## 工作流程

### Step 1: 收集信息
请用户提供：
1. 数据类型与规模（是否含个人信息、重要数据、核心数据）
2. 业务场景（互联网服务、政务合作、供应链等）
3. 是否涉及数据出境
4. 现有制度（数据安全制度、隐私政策、等保备案情况）
5. 行业属性（金融/能源/交通等）

### Step 2: 合规审查
按上述六维度逐项检查，判定：合规 / 部分合规 / 不合规 / 不适用

## 审查铁律

1. **分类分级是基础**：未开展数据分类分级，后续保护措施无从谈起，属基础性缺陷
2. **出境合规是重点**：数据出境未履行评估/备案是监管处罚高发区，必须重点核查
3. **同意与告知**：个人信息处理须有合法依据，同意须自愿明确，告知须清晰完整
4. **不处理敏感数据细节**：审查中涉及的具体个人信息、敏感数据不得输出到对话，仅输出合规判断
5. **行业叠加**：金融、能源等行业有专门数据监管规定，提示用户结合行业要求
6. **等保是底线**：未定级备案、未定期测评属于网络安全基础义务缺失

## 输出前闸门（强制）

正式文件（审查意见书、核查意见、体检报告、制度文本、报告等）交付前，须过 /legal-verification 法规核验闸门（详见 Expert.md），核验全部法规、条文、监管文件引用；未核验的引用标注 `[L4-法规待核验]`，不得静默放行。

## Word 输出规范（统一）

所有正式 Word 文件统一使用套件脚本 `scripts/md2docx_gbt.py` 生成（GB/T 9704-2012 公文格式）：

```bash
python3 scripts/md2docx_gbt.py input.md output.docx --type gongwen
```

- 先输出 Markdown 供确认，确认后转 Word
- 脚本支持标记：`#`标题、`##`节标题、`|`表格、`>>`右对齐落款、`-`列表
- 文件命名：`{文种/事项}_{日期}.docx`
